# 练迹

简体中文、手机优先的个人健身记录网页。运行入口仍然是仓库根目录的单文件 `index.html`，无需构建、登录或配置 API 密钥。

## 智能做饭（v1.1）

打开原来的“饮食”页即可使用。输入食材名称，选择炒锅、空气炸锅，设置备餐份数及每份用油量，然后生成菜谱。菜谱包含建议克数、每份与整次备餐的估算营养、分步骤做法、火力/温度和参考时间。可收藏，并按实际吃下的份量写入原有饮食记录和当日统计。

本功能使用本地规则匹配常见食材，并非联网大模型。当前支持鸡胸肉、洋葱、鸡蛋、杂粮馒头、西兰花、胡萝卜、土豆、番茄、黄瓜、豆腐、米饭、红薯。只输入名称；输入的库存数量不会被读取。未识别食材明确列出，不计入菜谱。蔬菜或主食单独生成时，会提示缺少蛋白质等搭配限制。

营养按常见食材参考值估算，食用油计入，额外酱料未计入；不同品牌、配方和实际用量可能差别较大。有包装营养标签时优先按标签校正，必要时使用原“记录一餐”手动填写。

鸡胸肉须安全解冻。180℃、12–16分钟仅为完全解冻后、厚约1.5–2cm鸡胸肉的参考，不能按时间保证熟透；必须用食品温度计确认最厚处中心至少74℃。页面包含冷藏/冷水解冻、分批烹饪、生熟分开说明及 FDA、USDA、FoodSafety.gov 原始依据链接。

## 本地数据与兼容

- 原有12周训练计划、17个独立中文B站视频入口、重量、打卡、体测和恢复记录保持保留。
- 继续使用 `lianji-v1` 和 `schema: 1`，仅增加可选的 `cooking` 字段。导入旧备份会补充做饭默认值；新完整备份同时包含收藏。
- 损坏的原始存储不会被默认数据自动覆盖。界面提供原始存储导出和有效备份恢复入口。
- 数据属于当前浏览器和网址，不自动跨设备同步。更换访问地址、浏览器或设备前，先在“数据与备份”导出 JSON，再在新地址导入。
- 旧版程序不认识新增收藏字段；不要把新备份交回旧程序后覆盖保存。请保留原始备份文件。

## GitHub Pages

仓库中的代码提交不代表网站已发布。若 Pages 尚未开启，在仓库 Settings → Pages 中将 Source 设为 **Deploy from a branch**，选择 **main** 和 **/(root)**，点击 Save。随后检查 Pages 部署运行结果，以及 Settings → Pages 的 Visit site 地址。

只在部署成功、HTTPS实际返回200且显示当前版本后，才确认上线。GitHub 项目站点的预期路径为 `https://7hbn55yykk-tech.github.io/lianji-fitness/`；该地址的实时可用性需要另行验证。

## 开发验证

网页本身没有第三方运行依赖。测试使用 Node.js 22+；浏览器测试使用 Playwright。

```sh
npm install
npx playwright install chromium
npm test
npm run test:browser
```

核心测试覆盖旧数据兼容、原计划及视频保留、收藏备份校验、菜谱匹配和份量/营养计算。浏览器测试覆盖训练重量保存、刷新继续训练、做饭收藏和记录、导出导入及手机窄屏布局。截图默认写入系统临时目录，可通过 `LIANJI_TEST_OUTPUT` 指定位置。B站测试核对原有独立链接保留，不代表第三方视频在所有网络可播放。
